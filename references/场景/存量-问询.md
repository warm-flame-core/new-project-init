## 本场景核心

> **本场景核心：改已有文档必须谨慎。** 进入前强制声明限制规则 R1-R5（+R6），遵守后才开始问询。

## 限制规则（硬规则）

- **R1 进度必须用户口述**：进入存量完善前，**强制让用户反馈当前项目进行到哪**（哪个模块/做到什么阶段/最近在做什么）；用户说得乱也**全部记录**——乱本身就是信息（能看出实际状态与文档是否一致）。🔴 **禁止**：用户说「你自己去看代码/记忆」就去看——agent 可以先听口述，**之后**再读记忆库/git 核实，但**进度基线必须以用户口述为准**，不能自己推断（进度口述 vs 技术实测的分层见中途问询「信息分层原则」）。
- **R2 在途模块隔离**：用户反馈「某模块开发到一半 / 审查中 / 测试中」→ **该模块相关的全部文档（specs 五件套/记忆库状态/任务清单条目）禁止改动**，只允许「记录现状」；只完善「不在途」的部分（规范文件/未开始模块/通用文档）。理由：改在途模块文档 = 干扰正在进行的开发，可能造成进度丢失。
- **R3 工作区谨慎**：有未提交改动 → 先弄清改动来源（git status + 用户口述交叉），不擅自整理/丢弃；未提交改动涉及的文档按 R2 隔离。
- **R4 写操作确认**（沿用全局）：涉及数据库/迁移 → 写操作展示 SQL 获用户确认；涉及 git → commit 需用户允许。
- **R5 范围逐项确认**：差距诊断完成后，**逐项与用户确认「这项要不要补/怎么补」**，不默认全补；大改动（如引入 agents + 闭环工作流）单独确认后才动。
- **R6 改造边界（只记录不重构）**：存量完善期间对**现有代码只记录不重构**——发现的结构性问题（文件过大/边界不清/职责纠缠）记入演进任务清单/技术债务，**不在补建文档体系时顺手改**（改代码是另一个工作流，避免把文档完善变成代码改造）。

# 存量完善执行：文档冲突消解与联动核查流程

> 目标：确保补齐后**所有文档之间有联系（索引完整）且无冲突（无重复权威、无矛盾内容）**——防「维护一边另一边漂移，下一次 agents 看就跑偏」。**阶段 0 + A/B/C 四阶段按序执行，每阶段产出须用户确认。**

## 阶段 0：工作流闭环核查（v10.0 新增，反馈：存量完善场景「文档还行但工作流不闭环」）

- **诊断**：不只查文档，还查**工作流是否闭环**——①agents 角色/签署矩阵是否落地（谁产出谁签署，有无代签/漏签）②记忆纪律是否闭环（logs 跨天拆分/动作标签引用/入场核对是否执行）③会话管理是否闭环（交接文档时机/上下文管理提醒）④多边维护信息是否有唯一出处（无 → 按阶段 B 去重）。
- **产出**：工作流缺口清单（同文档差距清单一起），**随 R5 逐项确认**——文档还行但工作流不闭环的部分，一并补进对应模板产出物（如 CLAUDE.md 签署矩阵缺「追加 vs 更新」区分 → 补；logs 无跨天拆分规则 → 按模板 05 补）。
- **原则**：只记录不重构（R6 同适用）；工作流缺口按「规范文件缺 → 补规范，流程缺 → 补模板产出物对应节」处理，不顺手改业务代码。

## 阶段 A：冲突消解（每份被改造文档）

1. **差异诊断**：逐节对照对应模板，产出差异清单（模板有/文档缺、模板无/文档多、双方都有但内容冲突）
2. **冲突分类 + 裁决**（按信息分层原则）：
   - 模板规范 vs 项目实际 → **以项目实际为准**（模板只供结构参考），差异记录进演进清单
   - 新旧文档内容冲突 → **以用户口述/代码实测为准**，被否一方标注废弃
3. 每处冲突选定动作（保留原文 / 按模板改 / 删除 / 标注待定），**逐项用户确认**（R5）

## 阶段 B：重复去重（跨文档）

4. **重复扫描**：同一信息是否在多处出现（如「验收门槛」可能同时出现在 CLAUDE.md、演进清单、测试手册、specs 模板）
5. **唯一出处裁定**：每条重复信息指定唯一出处（通常 CLAUDE.md C 区），其余位置**改为引用不复制**
6. 引用格式：`见 CLAUDE.md C 区「记忆库纪律」`（交叉引用而非复制——唯一出处原则）

## 阶段 C：索引核查（收尾必做）

7. **三层索引核对**：file-index ↔ 实际文件清单；CLAUDE.md 文档索引 ↔ docs/ 实际文档；DOCUMENT-INDEX ↔ 全部规范/模板/文档
8. **链接检查**：文档内所有引用能否找到目标，断链 → 修复或删除引用（含死引用：引用了不存在的文件）
9. 每份改动文档末尾变更记录追加一行（**行内标注性质**：新增/修改/删除/去重，见文档维护规则第 7 条）
10. **入场核对联动**：此后新会话入场核对发现文档间不一致 → **按本流程处理，不自行裁决**（记忆纪律第 3 条补充）
11. **变更记录方向核查（v10.3/v10.4/v10.5）**：核对各文档变更记录是否按「文档维护规则第 9 条」方向（纯 AI=头插 / 有人看=尾插）；发现乱序/方向混用（过渡态）→ **向用户展示该文档过渡态现状**（新旧混排表格，让用户直观看到问题）→ 提供两档规整选择（第 9 条「存量规整」）：
    - **档 1 逐文档**（推荐）：用户逐文档确认后重排 + 加规整标记行
    - **档 2 全查全规整**（激进）：一次性规整全部文档——**说明为什么不推荐**（违反逐项确认/可能误伤在途文档/工作量大出错高）后，用户仍坚持才执行
    - 用户不确认 → 保留原样（默认不动，R5 逐项确认）
