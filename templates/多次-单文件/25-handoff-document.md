# memory/handoff/<模块>-交接文档.md 章节模板（模板 25）
> 🗂️ **产出模式**：多次创建-单文件（无文件夹，复制特化模板文件新建）；模板目录：templates/多次-单文件/（v10.0 目录规整）
> 📍 **变更记录方向**：新行插顶部（纯 AI 看；见 SKILL.md 文档维护规则第 9 条）

> ⚠️ **维护声明**：交接文档是**临时文件**（给 agent 看，看完删或改名归档），**不写变更记录表**；其生命周期规则见 SKILL.md H4（memory/handoff/，看完删或改名归档进 archive/，要点同步记忆库三件套）。
> 模板用途：**每次开新会话/跨阶段交接时**创建的「多次创建文件」。新会话 agent 入场读完交接文档并完成对应工作后，**删除该文件**（或按 H4 改名归档），并在 `agent-activity-log.md` 记一行（含删除说明），保证删后无残留。
> 核心设计：**§1 文档签署状态清单是必填表**——解决「换新会话时 plan 审批状态、acceptance 签署状态等信息丢失」（PTB-IMP perm-001 实测教训：plan §9 只有 Planner「待审批」行，用户已批准但换会话后无人回填）。
> 配套：签署责任矩阵见模板 24；plan §9 用户审批行见模板 17。

## 第一部分：简化章节递归（结构一览）

```
memory/handoff/<模块>-交接文档.md
├── # <模块> 交接文档（<日期>，交接人：<三元组署名>）
├── ## 0. 一句话状态        ← 统一格式：<状态符号> <模块>：<进展> + 下一会话第一动作（状态符号见模板 02 §6）
├── ## 1. 文档签署状态清单（必填表）← 逐文档核对：版本/已签状态/还欠谁/接手动作
├── ## 2. 已同步记忆库要点    ← 本会话已落盘的（project-context/file-index/activity-log/logs）
├── ## 3. 下会话必做清单     ← 第一动作=核对 §1 欠签回填；任务性待办
├── ## 4. 环境/凭据/数据现状 ← 迁移应用情况、缓存、冒烟数据、临时工具
└── ## 5. 遗留风险/技术债    ← 未决问题、技术债务登记
```

## 第二部分：详细规格

### 文件命名与位置
- 路径：`memory/handoff/<模块>-交接文档.md`（如 `module-011-交接文档.md`、`权限改造-交接文档.md`）；**不放 docs/、specs/**。
- 创建时机：①会话上下文压缩 1 次后准备开新会话 ②阶段边界（开发→审查、审查→测试）③用户指示换会话。
- 处理方式（按 H4 答案）：完成即删 / 改名归档进 `memory/handoff/archive/`；**删除前必须确认要点已同步记忆库三件套 + activity-log 记一行含删除说明**。
- 📌 **日期纪律（v10.0）**：交接文档头部日期 = 实际创建当天（系统日期为准）；§1 签署状态清单每行的「签署人+日期」标注实际签署日（欠签留空，不预写）；交接文档是临时文件不写变更记录表。

### §0 一句话状态（格式标准化）
- **统一格式**：`<状态符号> <模块>：<进展>` + 下一会话第一动作，一行写完。
- **状态符号与 project-context §6 一致**（模板 02）：📋 待开发 / 🔧 开发中 / 👀 待审查 / 🧪 待测试 / ✅ 已完成——新会话一眼定位在哪个阶段。
- 示例：`👀 perm-001 权限地基：编码完成 879 绿，待审查；下一会话第一动作=独立审查`。

### §1 文档签署状态清单（必填表，本模板核心）
```
| 文档 | 版本 | 创建者 | 已签署/审批状态 | 签署人+日期 | 还欠谁 | 接手动作 |
|------|------|--------|----------------|-------------|--------|----------|
| plan.md §9 用户审批 | v1.0 | Planner | 📋 待审批（用户已口头同意？→ 标注） | 用户 | 回填用户行 | Developer 入场第一件事：若用户已批 → 回填 ✅ 已批准 |
| acceptance §签署区 | v1.0 | Planner | 留空 | - | Tester | Tester 测试后填「测试人+结论+日期」 |
| changelog | - | - | 未产出 | - | Developer | 开发完成时产出 |
| review-report | - | - | 未产出 | - | Reviewer | 独立审查后产出 |
| test-report | - | - | 未产出 | - | Tester | 测试后产出 |
```
- 字段要求：状态写「✅ 已签 / 📋 待审批 / 留空 / 未产出」；**「还欠谁」必须填**——这是防遗忘的关键列。
- 逐文档核对，不遗漏五件套 + 用户审批行 + 任务清单。

### §2 已同步记忆库要点
- 本会话已落盘内容：project-context（改了哪些节/状态）、file-index（新增哪些行）、agent-activity-log（记了几行）、logs（哪些文件）。让新会话知道「哪些已同步、无需重做」。

### §3 下会话必做清单
- **第一动作固定写：核对 §1 清单，欠签的立即回填（plan 用户审批行 / acceptance 签署区等）**。
- 任务性待办：未完成的子任务、待补测项、待应用迁移等（checkbox 形式）。

### §4 环境/凭据/数据现状
- 迁移脚本应用情况（如 V31 已应用共享库）；Redis 缓存需清；冒烟数据待清理（DELETE 需用户确认）；临时工具 `.tmp-xxx/` 位置（用后即删）。
- 凭据只在记忆库记录，交接文档引用位置即可，不重复贴敏感信息。

### §5 遗留风险/技术债
- 未决问题（如 vue-tsc 已知技术债）、Reviewer nits、待 lead 决策项。
