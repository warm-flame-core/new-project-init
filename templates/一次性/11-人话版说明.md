## 第一部分：章节结构一览

```
docs/功能说明-人话版.md
├── # <项目名> - 功能说明（人话版）
├── ## 一、这平台是干嘛的？一句话
├── ## 二、<N> 种角色，各是什么人
├── ## 三、角色之间啥关系？（重点）
├── ## 四、每个角色手里具体有啥功能
├── ## 五、用两个场景把全流程串一遍
├── ## 六、几个容易懵的点，人话解释
└── ## 七、一句话总结关系网
```

## 第二部分：详细规格 + 示例

- **一、一句话**：不用术语的一句话（如「一个帮学校和公司牵线的网站」）。
- **二、角色**：每个角色用「是什么人」讲（如「学校管理员 = 学校负责这事的人」），不用「XX_ADMIN」。
- **三、关系**：角色之间怎么协作（谁给谁审批、谁发布谁报名），可配简单示意图。
- **四、每角色功能**：按角色列「手里有啥」。
- **五、场景串流程**：选 1-2 个完整业务场景从头走到尾（如「一家公司想招实习生」→ 注册 → 审核 → 发布岗位 → 学生投递）。
- **六、易懵点**：最容易困惑的点（如「为什么注册后不能马上登录」「审核不过怎么办」）。
- **七、总结**：一句话关系网。

### 示例（结构示范）
```markdown
# 高校企业对接管理平台 - 功能说明（人话版）

## 一、这平台是干嘛的？一句话
一个帮学校、培训机构和公司互相牵线的网站：学生想找实习/培训，公司想招人，平台负责把两边对起来。

## 二、六种角色，各是什么人
- 平台管理员：管平台的运营人员，负责审核和看后台
- 学校管理员：学校派来管理学生信息的人
- 学生：想找实习、报名培训的同学
- …

## 三、角色之间啥关系？
公司/机构 → 提交资料给平台审核 → 审核过了才能用 → 发布岗位/项目 → 学生来报名

## 五、用两个场景把全流程串一遍
场景 1：一家公司想招实习生。注册 → 填资质材料 → 等平台审核（1-2 天）→ 通过后发布岗位 → 学生投简历 → 公司挑人。

## 六、几个容易懵的点
- 为什么注册后不能马上登录？因为要先过资质审核，审核通过系统才开账号。

## 七、一句话总结关系网
平台管门禁（审核资质），学校管学生，机构/公司发布机会，学生报名参与。
```
