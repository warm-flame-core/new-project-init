```
PR 处理规范

├── 提 PR 清单（提交前逐项自查）
```

## 第二部分：详细规格（写什么 / 格式 / 示例）

### 1. 提 PR 纪律（硬规则）

- **模板必填**：提 PR 前先读仓库 PR 模板（`.github/PULL_REQUEST_TEMPLATE.md` 或平台对应路径），所有必填项填全——**缺模板结构 = 退回**。
- **搜重复**：提 PR 前先搜 open + closed 是否有同主题 PR，防重复提交/撞车；有则在其上跟进，不另开。
- **真人痕迹**：提交前必须**真人 review 完整 diff**——无真人确认痕迹的 PR 会被拒（AI 代提的低质量 PR 不予合并）。**Agent 只协助起草与检查，最终提交前由真人放行。**
- **单主题不打包不批量**：一个 PR 只做一个主题；不分装无关改动（refactor 与 feat 混提、多 bug 打包 = 退回）。

### 2. 提 PR 清单（提交前逐项自查）

- [ ] 分支命名符合规范（feat/fix/hotfix/release 全小写连字符）
- [ ] 已 rebase 到最新 main + 冲突解决 + 合并结果跑全量测试绿
- [ ] PR 标题一句说清主题；描述填全：变更说明 / 变更类型 / 关联信息 / 改动范围 / 测试情况
- [ ] 非主题改动已拆出，未混提
- [ ] 真人已 review 完整 diff 并确认（有真人痕迹）
- [ ] 无敏感信息（密钥/内网地址/凭据）入库

### 3. 审他人 PR（验收标准 = 最终实现）

- **逐条核对**：审 PR 时按「验收标准 = 最终实现」逐条核对（复用模板 20 阶段 §3 强项）——acceptance/描述声明与代码实际行为不一致时，先同步描述再签。
- **分问题分级**：阻塞（bug/不变量破坏/验收项遗漏）/ 建议（可优化），每条给根因 + 修复示例。
- **不代签**：谁审查谁签署，禁止代签；发现实现缺陷退回提交者逐条修复。

### 4. PR 模板接续

- 仓库 `CONTRIBUTING.md` 的 PR 模板已定结构；本规范是它的**执行纪律层**（提 PR 必填/搜重/真人痕迹/单主题），两者配合使用。
