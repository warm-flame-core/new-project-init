# docs/功能说明.md 章节模板（模板 09）
> 🗂️ **产出模式**：一次性文档（skill 特化即正式文件，后续修改=更新式：改内容+变更记录+署名）；模板目录：templates/一次性/（v10.0 目录规整）
> 📍 **变更记录方向**：新行追加底部（有人看；见 SKILL.md 文档维护规则第 9 条）

> ⚠️ **维护声明**：本文档修改后必须在末尾「变更记录」表追加一行——`YYYY-MM-DD HH:mm | 变更内容 | 署名`（署名按三元组 人-角色-实例，如 张三-Developer-lead；无法确认实例先问用户）。
> **一次性文档**（E1 选「功能说明」时产出）。示例写在开头，agents 按问询答案追加/替换填写。
> 定位：给**需求方/开发团队**看的功能全貌，讲「系统有哪些功能、给谁用、怎么流转」，不含技术实现细节。

---

## 第一部分：章节结构一览

```
docs/功能说明.md
├── # <项目名> - 功能说明
├── ## 一、概述           ← 项目定位 + 目标用户 + 一句话价值
├── ## 二、角色           ← 角色清单 + 每人一句话职责（D9）
├── ## 三、功能模块       ← 按业务模块列功能点（用户视角）
├── ## 四、核心流程       ← 关键业务流转（注册→审核→使用）
└── ## 五、非功能需求     ← 性能/安全/合规（E6=要时；F2/F3 答案）
```

## 第二部分：详细规格 + 示例

### 一、概述
- 项目是什么、解决什么问题、给谁用。
### 二、角色
- 表：`角色 | 是谁 | 主要做什么`（按 D9 角色清单）。
### 三、功能模块
- 每个模块一个 `###`：模块目标 + 功能点列表（用户能感知的功能）。
### 四、核心流程
- 关键业务流：如「注册 → 资质审核 → 开通账号 → 使用」逐步描述。
### 五、非功能需求
- 性能（并发/响应）、安全（认证/权限/敏感数据，F2/F3）、合规（等保/GDPR 等，F3）。

### 示例（结构示范，内容按项目特化）
```markdown
# 高校企业对接管理平台 - 功能说明

## 一、概述
学校、培训机构、企业、学生之间的委托培训、实习、就业对接平台，解决校企对接信息不透明、流程线下化的问题。

## 二、角色
| 角色 | 是谁 | 主要做什么 |
|------|------|-----------|
| 平台管理员 | 运营方 | 审核资质、管理账号、查看审计日志 |
| 学校管理员 | 学校 | 管理学生、发布需求 |
| 学生 | 学生 | 报名培训、投递岗位 |
| … | | |

## 三、功能模块
### 资质审核
- 学校/机构/企业提交资质材料
- 平台审核通过后开通账号
### 培训班
- 机构发布培训项目 → 平台审核 → 学生报名

## 四、核心流程
1. 主体注册（提交资质材料）→ 2. 平台审核 → 3. 开通账号 → 4. 登录使用业务功能

## 五、非功能需求
- 性能：常规接口响应 <500ms；列表单页上限 500 条
- 安全：密码 BCrypt 存储；敏感数据（身份证/手机号）脱敏展示
```
