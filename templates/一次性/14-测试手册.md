## 第二部分：详细规格 + 示例

### 0. 通用准备（必填，新测试者第一步）
- 环境与启动命令（前后端、数据库迁移执行顺序，**实测**）。
- 账号清单：`账号 | 角色 | 密码（只写规则）`，如 `platform_admin | 平台管理员 | admin123（测试用）`。
- 注意事项（如「冒烟数据测完要清理，DELETE 需用户确认」）。
- 🔴 **测试前查库确认数据范围目标**：登录测试前，先查库确认测试目标账号在操作者的数据范围内（如学校管理员要操作的学生需 school_id 匹配）；范围内无匹配目标时，先经用户确认临时绑定/补充再测，测后还原基线——避免「操作者列表为空」误判为 bug。
- ⚠️ **冒烟数据影响人工测试（v10.12）**：若 Tester 冒烟**保留**了测试数据（唯一键/查重/状态机/审批流等），这些数据会**挡人工测试对应步骤**（如「已存在双身份关联或申请」）——手册必须在模块节的「测试数据前置」标注：**哪些保留冒烟数据需先清理或换成新数据**（冒烟数据清理需用户确认，见命令实测纪律）。

### 每模块节（复制追加模板）
```
## N. module-XXX：<模块名>
### 改了什么页面
- 本模块改了哪些页面/路由/按钮（业务视角，3-5 行）
### 涉及代码
- 后端：<Controller/Service 等改动要点>
- 前端：<页面/组件改动要点>
- 数据：<DDL/种子/迁移说明>
### 人工测试步骤（含预期）
1. 步骤 1（操作）→ 预期结果 A
2. 步骤 2（操作）→ 预期结果 B…
### 涉及账号/数据
- 需要的账号、准备的数据、测完清理方式
- **测试数据前置 / 需清理项（v10.12）**：本步依赖的测试数据（尤其 Tester 冒烟保留的唯一键/查重/状态机类数据）——先清理或换数据再测，避免撞业务前置。
```
- **每个步骤可执行**：写明点哪个按钮、填什么、看什么、**预期什么**，不允许「验证一下功能」这种模糊指令。

### 示例（结构示范，摘自本项目测试手册风格）
```markdown
## 0. 通用准备
- 启动：cd backend && mvn spring-boot:run（8080）；cd frontend && npm run dev（3000）
- 账号：platform_admin / admin123（测试用）；school_admin1 / admin123
- 注意：测试产生的临时数据测完请记录，清理需用户确认

## 1. module-001：PTB 角色体系对齐（新增市级监管员）
### 改了什么页面
- 新增「市级监管员」角色，可登录查看首页与审计日志，不可操作审核。
### 涉及代码
- 后端：RoleEnum + 种子账号；前端：SidebarMenu 角色分支
### 人工测试步骤（含预期）
1. 用 city_regulator 登录 → 登录成功
2. 查看侧边栏 → 应只有首页 + 审计日志
3. 尝试打开资质审核页 → 应被拦截（403）
### 涉及账号/数据
- city_regulator（密码 admin123）；测完无需清理（种子账号）
```
