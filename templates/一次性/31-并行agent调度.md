## 第二部分：详细规格（写什么 / 格式 / 示例）

### 1. 术语与平台能力

- **subagent（子代理）**：独立上下文的一次性 agent，只回最终结论，不进主线上下文（省 token、隔离上下文）。
- **并行 vs 串行**：只有**任务可拆、结果可独立**时才并行；父子依赖（一个结果是另一个输入）必须串行。
- 平台工具：Reasonix 用 `task`/`subagent`/`review`/`wait`/`explore`；DSH 用 `subagent`/`subagent_fork`（大规模并行用 `workflow`）——均不做写操作默认（见装配备注）。

### 2. 何时并行（判定）

- **只读并行（推荐首选）**：探索、多文件审查、独立事实查证（如"分别核这些模块的模块状态"）——可放心并行，不涉及共享可变状态。
- **写文件并行（谨慎）**：模块各自产 specs 文件、工作流并行执行——**必须配 BL-01 worktree 隔离**，避免同一文件/同一目录并发写撞车。
- **禁止并行**：同一文件多 agent 同时写、共享全局配置/依赖清单/迁移文件的并发改、有前后依赖的流程。

### 3. 调度纪律（硬规则）

1. **任务拆分**：先切成无重叠的任务集，每任务给**明确输入 + 明确产出路径**。
2. **只读/写区分标识**：调度清单里标注每任务是「只读」（不落盘、留在子上下文就好）还是「写」（落盘到指定 worktree 路径）。
3. **冲突域检查**：并行写任务开工前，先核对任务间**共享文件集合是否为空**；非空则改串行或重新分配。
4. **上下文隔离**：并行子代理互不可见，各自独立；汇总由主线（Planner/调度者）统一做，不在子代理间横向传状态。
5. **记忆库纪律仍生效**：每个写文件子代理完成后，把产出登记进记忆库三件套（agent-activity-log 各记一行）；只读子代理结论由调度者代为登记结论，不落失。

### 4. 聚合与收尾

- **等全部返回**：`wait` 全部子代理返回后再统一盘点，不逐个穿插打断（打断易导致现场碎片化）。
- **逐个归并**：把各子代理结论映射到对应任务 / 文件，逐条核对「产出即完成、缺即补齐」。
- **冲突裁决**：并行结论若对同一决策给出不同答案 → 不合并，停下来用「技术实测 / 用户口述」权威来源裁决（见信息分层原则），不默认取并集。

### 5. 与工作区隔离（BL-01）衔接

- 写文件并行 → 每个写任务落到**独立 worktree**（模板 30 §4）；只读任务可共用只读目录。
- 收尾：全部合并后单一干净工作区跑全量回归再 push（模板 24 阶段 6 / 模板 28 §5）。

### 示例（摘自 PTB-IMP 并行审查调度记录，结构脱敏）

```markdown
- 任务：并行读 4 个模块的 review-report 核对验收条
- 调度：4 个只读 subagent，各自 module-XXX，无需 worktree
- 聚合：wait 全返 → 逐条核对缺项 → 汇总差异给 Reviewer 裁决
- 结果：A/B/C 通过，D 阻塞 → 单条退回 Developer 修复后复审
```
