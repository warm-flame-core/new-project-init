# CLAUDE.md 章节模板（模板 01）
> 🗂️ **产出模式**：一次性文档（skill 特化即正式文件，后续修改=更新式：改内容+变更记录+署名）；模板目录：templates/一次性/（v10.0 目录规整）
> 📍 **变更记录方向**：新行追加底部（有人看；见 SKILL.md 文档维护规则第 9 条）

> ⚠️ **维护声明**：本文档修改后必须在末尾「变更记录」表追加一行——`YYYY-MM-DD HH:mm | 变更内容 | 署名`（署名按三元组 人-角色-实例，如 张三-Developer-lead；无法确认实例先问用户）。
> **一次性文档**（skill 只运行一次，后续所有开发都从 CLAUDE.md 入手）→ 本模板为全部模板中最详细的一份。
> 用法：第二部分逐节给出「写什么 / 格式 / 示例片段」（示例摘自 PTB-IMP 项目 CLAUDE.md 脱敏，仅作结构示范，禁止照抄内容）；agents 按问询答案逐节替换为项目实际情况，示例残留内容要清干净。
> **双受众定位**：CLAUDE.md 给人看 + AI 入场必读（AI 每次入场完整读一遍，token 成本敏感）→ 内容按「三因素」取舍（见产出红线⑤）。
> **产出红线**：
> ① 常用命令必须**实测**（写错构建命令比不写更糟）
> ② 认证/取当前用户约定必须写清
> ③ 敏感信息（内网地址/密码/凭据）不写
> ④ 问询纪律（记忆/会话/工具/写操作确认）落入**正文对应区**——记忆纪律进 C 区、纪律红线进 A 区、会话上下文进 D 区引用（不再笼统塞附录）
> ⑤ **三因素取舍**：双受众高频节（A/B 区）= 详细但精炼（表格化、要点化，人读得懂、AI 不啰嗦）；仅 agent 操作节（C 区）= 简洁速查清单（AI 能看懂即可，不追求文档排版）；低频长流程（D 区）= 只留一行引用、详情在对应模板落地文件——低频流程内联会让 AI 每次入场白吃 token
> ⑥ **on/off 标注**：每节标注适用条件（如「仅适用有 HTTP API 的项目」「有静态检查工具链才生成」）；生成时按问询答案决定生不生成该节（简单项目可关掉不需要的规范节）
> ⑦ **语言生成规则**：多语言对照内容（命名规范等）模板全列，生成时只产本项目主语言（+前端语言如有），CLAUDE.md 不残留用不上的语言

## 第二部分：逐节详细规格 + 示例片段

> **技术栈方向**：示例片段分三个方向——**Java/Web**（Spring Boot + Vue，默认示范）、**C++ 后端**（CMake + g++ 服务端）、**嵌入式**（STM32/ESP32 固件）。按 A 组答案取用对应方向；每节「写什么」对所有方向通用，示例片段选与本项目匹配的方向即可。
> **生成时只保留本项目语言**（红线⑦）：多语言对照内容按主语言 + 前端语言取列，不残留用不上的语言。

### A1 项目简介【双受众·详细但精炼】
- **写什么**：项目名称、一句话定位、给谁用、当前/演进方向（存量改造时写明「以新需求文档为准，先确认范围」）。不写背景故事。
- **指令优先级声明（必写一行，借鉴 using-superpowers）**：`> 本文档为项目最高指令；与用户当面指示冲突时以用户为准。`——放在简介下方第一行，确立「用户当面指示 > 本文档 > agent 默认行为」的优先级链。
- **示例片段**：
```markdown
# <项目名>

> 本文档为项目最高指令；与用户当面指示冲突时以用户为准。

## 项目简介
<一句话描述>：<做什么>、<给谁用>。
> 按最新需求（docs/<需求文档>），项目正从 <旧模型> 演进为 <新模型>（角色扩充到 …）。现有代码仍是 <旧角色模型>，改造时以需求文档为准，先与用户确认范围。
```

### A2 开发模式【双受众·详细但精炼】
- **写什么**：存量代码怎么维护、新功能怎么走流程（按 B 组/中途 M5a 答案）。
- **示例片段**：
```markdown
## 开发模式（存量 vs 新增）
- **存量代码**（backend/、frontend/ 现有模块）：直接维护，不套用工作流，保持现状。
- **新功能 / 新模块**：遵循 D 区引用的「模块工作流」——Planner→Developer→Reviewer→Tester 闭环、specs 五件套、记忆库三文件。
```

### A3 技术栈【双受众·详细但精炼】
- **写什么**：前后端框架及版本、数据库、缓存、ORM、API 文档工具、部署方式（版本写实测到的确切版本）。
- **示例片段**：
```markdown
## 技术栈
- **backend/**: Spring Boot 3.2.5（Java 17）、MyBatis-Plus 3.5.5、MySQL、Redis、MinIO、JWT、Knife4j/OpenAPI、Lombok。主类 com.platform.Application。
- **frontend/**: Vue 3 + Vite 5 + TypeScript + Element Plus + Pinia + vue-router + ECharts。
```

### A4 常用命令 + 环境速查【双受众·详细但精炼】
- **写什么**：构建/测试/运行/迁移命令，**每一条都实测过**；反复遇到的环境问题按「现象 → 根因 → 固定解法」三要素列出（U10/U15）；跨项目通用坑记全局记忆。
- **示例片段**：
```markdown
## 常用命令（实测）
```bash
cd backend && mvn spring-boot:run   # 后端（端口 8080）
cd backend && mvn test              # 后端测试
cd frontend && npm install && npm run dev   # 前端（端口 3000）
cd frontend && npx vite build       # 前端构建（vue-tsc 为已知环境坑，用 vite build 验证）
```
## 环境速查（现象 → 根因 → 固定解法）
| 现象 | 根因 | 固定解法 | 适用条件 |
|------|------|----------|----------|
| 自动化脚本含中文在 Windows 下执行失败 | Windows PowerShell 按 ANSI 读 UTF-8 无 BOM 脚本 | 脚本避免中文字面量（中文写临时文件再读） | Windows 环境 |
| AI 工具重写已存在文件后中文变乱码 | 工具保留原文件编码（如带 BOM） | 先删除再写新文件，或显式指定 UTF-8 无 BOM | AI 工具行为 |
| 业务校验失败返回 HTTP 400 而非统一信封 | 后端把业务异常映射为 HTTP 状态码 | 测试封装捕获 HTTP 错误读 body，别假设业务失败一定 200+code | 有 HTTP API 的项目 |
| Java 工具输出中文乱码 | 默认编码非 UTF-8 | 运行时加 `-Dfile.encoding=UTF-8` | Java |
| 控制台中文乱码 | 代码页非 UTF-8 | 先执行 `chcp 65001` | Windows |
```

### A5 架构【双受众·详细但精炼，按语言栈生成】
- **写什么**（本项目最重要的约定，缺了后续开发会踩坑）：按主语言生成对应小节——
  - Java/Web：**认证与当前用户**（登录机制 + Controller 取当前用户方式 + 权限模式）+ **统一返回与分页** + **配置红线**
  - C++：接口层→业务层→数据层 + 配置（环境变量/文件）+ 日志分级
  - 嵌入式：应用层→业务层→驱动层 + 中断与任务隔离 + 串口日志
  - 前端（如有）：api 封装 / 路由守卫 / 状态管理 / 设计风格
- **只写「后续开发必须知道的约定」，不写框架科普**。
- **示例片段（Java/Web）**：
```markdown
## 架构
扁平分层：controller → service（接口）+ service/impl（实现）→ mapper → entity/dto/vo，另有 config/security/common/enums/util。

### 认证与当前用户（关键约定，勿偏离）
- JwtAuthFilter 从 `Authorization: Bearer <token>` 解析 JWT，校验签名 + Redis 中 auth:token:{userId} 一致性。
- **Controller 取当前用户用 `request.getAttribute("userId")` / `getAttribute("role")`**，不是 @AuthenticationPrincipal。
- 权限为服务层按角色过滤数据：Service 方法接收 userId + 各主体 id，按角色缩小查询范围。

### 统一返回与分页
- Result<T> = { code, message, data }；code=200 成功，401 未认证/过期。
- 列表统一返回 Result<PageResult<T>>；分页依赖 MyBatis-Plus 分页拦截器（单页上限 500）。

### 配置
- application.yml（激活 dev profile）+ application-dev.yml；**不要把内网地址/凭据提交到公开仓库**。
```

### A8b 信息闭环图【双受众·人+AI 都能看懂】（v10.0 新增）

- **写什么**：项目内**多边维护信息的闭环总图**——每条「多处出现的信息」的 唯一出处（权威）→ 引用方（汇总视图）→ 同步方向 → 维护人/时机。目的：**人打开 CLAUDE.md 就能找到任何信息的权威位置**（人好找信息），agents 按 C 区速查执行（机器可读），两者共用同一张图。
- **按问询开关（on-off）**：图里的节点标注适用条件——**用户问询后不生成的文档（如 docs 某文档 E1 没选、agents 单人没建、tools 没建、file-templates F4 没选）画成虚线节点并标注「按问询生成」**；生成 CLAUDE.md 时按实际问询答案裁掉不存在的节点，只保留真实闭环。
- **示例片段（脱敏自 PTB-IMP，虚线=按问询生成的可选节点）**：
```markdown
## 信息闭环图（多处维护信息的唯一出处 + 引用关系）

> 规则：改信息时**只改唯一出处**，引用方自动生效（或按收尾四查同步）；改完检查引用方无漂移。
> 虚线节点 = 按问询生成的可选文档（你的项目没选就无此节点）。

### 闭环 1：模块状态（进度/验收）
- 唯一出处：任务清单 checkbox（主线 `docs/PTB演进任务清单.md` / 专项 `docs/PTB权限与角色改进任务清单.md`）

- 同步：模块完成后按「收尾四查·进度清单同步」逐项更新引用方；只改一处 = 漂移

### 闭环 2：签署责任矩阵
- 唯一出处：CLAUDE.md C 区「签署责任矩阵」
- 引用方：`memory/project/module-lifecycle-checklist.md`（阶段签署点）→ agents/*.md（各角色签署约束）→ specs 五件套签署区
- 同步：改矩阵时检查 checklist/agents 引用一致（只引用不复制）

### 闭环 3：动作标签（20 个）
- 唯一出处：CLAUDE.md C 区「动作标签表」
- 引用方：`memory/agent-activity-log.md` + `memory/logs/<角色>/<日期>.md`（只用标签不复制表）

### 闭环 4：文档三要素 / 收尾四查 / 大前提术语
- 三要素唯一出处：CLAUDE.md C 区；引用方：docs/、specs/、permission-specs/README（标注引用）
- 收尾四查唯一出处：CLAUDE.md C 区 + checklist 阶段 5（双处同步，防漂移）
- 大前提唯一出处：`docs/<设计文档>` §0；引用方：专项 README / 任务清单 / 各 plan（摘要 + 引用）

### 闭环 5（虚线）：人工测试手册
- 按问询生成（E1 选测试手册才有）；唯一出处：`docs/模块改动与人工测试手册.md`，每模块 Tester 追加一节

### A9 纪律红线【双受众·每条一句话】
- **写什么**：人定的规矩（人要看到自己定了什么）+ AI 必须遵守。3-4 条，一条一句不展开。
- **示例片段**：
```markdown
## 纪律红线
- **数据库写操作**（DDL/迁移/数据修改）先展示 SQL 获用户确认再执行；只读 SELECT 可直接跑。
- **工具依赖方向**：项目代码禁止引用 tools/；工具被删除后项目必须照常编译（删除演练）。
- **commit/push** 需用户明确允许，不主动执行。
```

### B 区 · 硬规范 15 项【双受众·详细但精炼】

> 统一骨架：每项四段——语言无关原则 / 本项目语言规则（生成时按主语言产出）/ 适用条件（on-off 标注）/ 示例。
> 生成时：① 按项目语言取对应列 ② 适用条件不满足的整节跳过 ③ B9 命名规范只产主语言 + 前端语言。

#### B9 命名规范
- **语言无关原则**：可读性优先；同一语言内大小写风格统一；禁止拼音缩写（业务术语除外）。
- **本项目语言规则**（模板全列 Java/Python/TS/Go/C，生成取本项目列）：
  - Java：类 PascalCase / 方法 camelCase / 常量 UPPER_SNAKE / 包全小写点分 / 表字段 snake_case
  - TS：组件 PascalCase / 工具函数 camelCase / 接口 PascalCase（无 I 前缀）
  - C：函数 snake_case / 类型 PascalCase / 宏 UPPER_SNAKE
  - Python：类 PascalCase / 函数 snake_case / 常量 UPPER_SNAKE / 模块 snake_case
  - Go：导出 PascalCase / 非导出 camelCase / 包小写单词
- **适用条件**：默认开（无此语言的项目跳过）。
- **示例**：`UserManageServiceImpl`（类）/ `resetPassword`（方法）。

#### B10 分层依赖
- **语言无关原则**：接口层→业务层→数据层单向依赖；禁反向、禁跨层；同层可互调但禁循环。
- **本项目语言规则**（按语言栈生成）：Java/Web：Controller→Service（接口）+Impl→Mapper→entity/dto/vo；DTO 使用层级（RequestDTO 仅 Controller 入参 / ResponseVO 仅出参 / Entity 只 Service↔Mapper）。C++：接口层→业务层→数据层。嵌入式：应用层→业务层→驱动层（中断与任务隔离）。
- **适用条件**：有分层需求才开（极简脚本项目可关）。
- **示例**：`Controller 不直接调 Mapper`（跨层禁止）。

#### B11 注释规范
- **语言无关原则**：对外/公开接口必注释；复杂逻辑（≥10 行）行内注释；魔法数字定义常量；TODO 带说明。
- **本项目语言规则**：Java=Javadoc（`/** */`）/ Python=docstring / TS=JSDoc（生成时按主语言）。
- **适用条件**：默认开。
- **示例**：`/** 用户注册 @param request … */`

#### B12 异常处理
- **语言无关原则**：禁空 catch（吞异常必须留注释+日志）；统一业务异常基类；全局异常处理器记完整堆栈；Controller 不吞异常。
- **本项目语言规则**：Java=BusinessException + @RestControllerAdvice / Python=自定义异常基类 + 全局 handler / C++=异常或错误码统一约定。
- **适用条件**：默认开。
- **示例**：`catch (BusinessException e) { log.error(..., e); }`（禁空 catch）。

#### B13 日志分级
- **语言无关原则**：ERROR（需人工介入）/ WARN（可恢复）/ INFO（关键流程节点）/ DEBUG（调试）；敏感信息（密码/手机号/身份证）禁打日志。
- **本项目语言规则**：Java=SLF4J+logback / 前端 console 分层 / 嵌入式串口日志分级。
- **适用条件**：默认开。
- **示例**：`log.info("用户注册成功, userId={}", id)`。

#### B14 代码长度限制（口径按 lead 样板）
- **语言无关原则**（三档）：
  - 单个方法/函数 ≤50 行：超过必须拆分；特殊情况（如长 switch、配置初始化）可在 plan.md 说明理由后放宽
  - 单个类/模块 ≤500 行：超过按职责拆分；特殊情况可在 plan.md 说明理由后放宽
  - 单个模块（module）≤200 行新增代码：单次迭代默认上限；复杂模块可在 plan.md 申请调整并说明理由
- **统计口径（核心）**：只统计**生产代码新增行**；docstring/注释/测试代码**单列统计且默认豁免**（Tester 产出不占模块行数上限）。
- **适用条件**：默认开。
- **示例**：模块改动 = 生产 200 行 + 注释 50 + 测试 50 → 注释/测试豁免后合规；模块若 250 行生产 → plan.md 说明理由申请放宽。

#### B15 安全 checklist
- **语言无关原则**：输入校验服务端必做（前端校验只是体验）；SQL 参数化禁拼接；密码强哈希（BCrypt/Argon2）；敏感配置走环境变量。
- **本项目语言规则**（按栈生成注入防护示例）：Java=PreparedStatement/MyBatis 参数 / 前端=XSS 转义 / 嵌入式=无 SQL 场景跳过本节。
- **适用条件**：默认开；无输入接口的固件项目可精简（只留密码/配置项）。
- **示例**：`SELECT * FROM user WHERE id=?`（参数化）。

#### B16 接口状态码
- **语言无关原则**：HTTP 语义统一——401=未认证 / 403=无权限 / 400=参数错 / 404 不存在 / 409 冲突 / 500 服务端 / 503 依赖不可用；业务失败用统一信封（code+message+data），不用 HTTP 状态硬编。
- **本项目语言规则**：统一返回结构 `{code, message, data}` + 分页 `{items, pagination}` + 业务错误码分段（1xxx 用户/2xxx 订单/9xxx 通用，按模块）。
- **适用条件**：仅适用有 HTTP API 的项目（纯嵌入式/无接口项目整节跳过）。
- **示例**：`{"code":200,"message":"ok","data":{}}`。

#### B17 版本管理
- **语言无关原则**：语义化版本号 `X.Y.Z-module-XXX`（主.次.修 + 模块号）；分支策略（main 稳定 + feature 开发）。
- **适用条件**：用 git 才开（无版本管理项目跳过）。
- **示例**：`v1.2.0-module-003`。

#### B18 提交信息格式
- **语言无关原则**：`[类型] 模块-XXX: 描述`；类型标签 feat/fix/refactor/docs/test/chore。
- **适用条件**：用 git 才开。
- **示例**：`[feat] module-005: 实现培训项目报名`。

#### B19 测试规范
- **语言无关原则**：单测/集成/回归分层；单测默认覆盖率 ≥80%（可调整需 plan 说明）；测试命名约定（`should_` / `testXxx`）；回归 100% 不得失败。
- **本项目语言规则**：Java=JUnit5+Mockito / Python=pytest / TS=Vitest / C++=ctest（生成时按主语言）。
- **适用条件**：默认开（嵌入式无测试框架则真机冒烟兜底）。
- **示例**：`mvn test`（全量回归绿）。

#### B20 静态检查
- **语言无关原则**：lint 跑在构建前，违例即构建失败；无工具链不硬造。
- **本项目语言规则**：Java=checkstyle / TS=eslint / Go=golangci-lint / C=clang-tidy（按项目已有工具写，未配的不写）。
- **适用条件**：有静态检查工具链才生成（问询确认；没有就整节跳过）。
- **示例**：`mvn checkstyle:check`。

#### B21 依赖管理
- **语言无关原则**：版本锁定文件**提交入库**（lock 文件）；依赖审计定期（npm audit / dependency-check）；不用「装最新版」。
- **适用条件**：有包管理器才开（嵌入式无包管理器跳过）。
- **示例**：`package-lock.json` 提交 / `npm audit`。

#### B22 超时/重试/降级
- **语言无关原则**：外部调用必设超时；可重试操作限次数 + 退避（禁无限重试）；依赖不可用降级不硬崩。
- **适用条件**：有外部依赖/服务调用才开（纯本地/固件可关）。
- **示例**：`HttpClient 超时 3s，重试 ≤2 次退避`。

#### C23 记忆库纪律
- **触发（任一必须写）**：开发改文件 / 测试（记结果数字）/ 审查（结论+遗留）/ git 实质操作（commit/push/merge/reset 记提交号；切分支轻量一行；fetch/pull/stash 与纯读不记）。
- **末尾自检三步**：①本轮动了哪些文件 ②记忆库是否已覆盖（project-context 更新日志 / file-index 新行 / activity-log 活动行 / logs 细档）③缺则补写。
- **入场核对（强制）**：读 project-context → file-index → activity-log → CLAUDE.md → handoff/（如有，看完删）；跑 git status + git diff --stat 与 file-index 核对，未知变动先弄清来源。
- **临时文件纪律**：临时脚本放 .tmp-xxx/（不入 git），用完即删，用法记 logs。

- **借口自查表（记忆纪律）**：

|------|------|

#### C24 签署责任矩阵（唯一出处，模板 24 只写「见 CLAUDE.md」）
| 文档 | 创建者 | 谁签署 | 签署时点 | 接手核对动作 |
|------|--------|--------|----------|--------------|
| plan.md | Planner | Planner 维护状态 + 用户/team-lead 审批 | 立项末→用户批复 | Developer 入场看审批记录，已批未回填立即回填 |
| acceptance | Planner | **只有 Tester** | 测试验收后 | Tester 接手第一步核对签署区留空/被代签 |
| changelog | Developer | Developer（每版追加） | 开发完成 | Reviewer 核对自测与代码一致 |
| review-report | Reviewer | Reviewer | 审查完成 | Tester 看结论是否 PASS |
| test-report | Tester | Tester | 测试完成 | team-lead/Developer 收尾核对 |
| 人工测试手册 | Tester | 无签署但必更新 + 用户实测 | 测试完成→用户确认 | 下模块参照样式 |

> 📌 **「追加 vs 更新」区分（v10.0，防无脑追加）**：签署/变更记录前先判断该文件类型——
> - **追加式（memory/ 三件套 + logs + 变更记录表）**：只在末尾追加新行/新表项，**不改旧内容**。
> - **更新式（docs/、specs/ 正文、agents/）**：改内容 + 末尾变更记录追加一行 + 署名；**正文不可只追加不更新**（内容与变更记录必须同步）。
> - **签署必带日期**：签署区/变更记录日期 = 实际签署当天（系统日期为准），禁止沿用旧日期或预写未来日期；写错用 [CORRECT] 追加更正，不删改原记录。

**防遗忘五机制**：①禁止代签（创建者只签自己的区）②接手必核对（每阶段入口核对前序签署）③签署即完成（没跑冒烟不许签 acceptance、没独立审查不许签 review-report）④**commit 前置 = 用户人工测试通过**（未获用户按手册实测并回报「通过」前，不允许 git commit；阶段 5 同步保留此前置，两处修改须同步防漂移）⑤**todo 强制 gate**（「人工测试反馈闭环」「收尾四查」必须拆成独立阻塞步骤，不允许揉进其他步骤顺带做，靠一步一签核卡住；**接口冒烟 ≠ 人工测试**——Tester 自测通过 ≠ 用户实测通过，未获「通过」反馈前 commit 步骤保持 pending）。
