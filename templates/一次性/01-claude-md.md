# CLAUDE.md 章节模板（模板 01）
> 🗂️ **产出模式**：一次性文档（skill 特化即正式文件，后续修改=更新式：改内容+变更记录+署名）；模板目录：templates/一次性/（v10.0 目录规整）
> 📍 **变更记录方向**：新行追加底部（有人看；见 SKILL.md 文档维护规则第 9 条）

> ⚠️ **维护声明**：本文档修改后必须在末尾「变更记录」表追加一行——`YYYY-MM-DD HH:mm | 变更内容 | 署名`（署名按四段式 实体人-平台-角色@分支（无 git 省略 @分支，如 warmflame-Reasonix-Developer@feat/xxx）；无法确认身份先问用户）。
> **一次性文档**（skill 只运行一次，后续所有开发都从 `<入口规范文件>` 入手）。
> 🔑 **平台入口映射（v11.0，ISSUE-013）**：本模板产出的是**入口规范正文**（默认文件名 `CLAUDE.md`）；**文件名由问询主导平台经映射表定**（主导=Claude→`CLAUDE.md`、Reasonix→`AGENTS.md`、Gemini→`GEMINI.md`、**ZCode/WorkBuddy/DSH→`AGENTS.md`**，见 SKILL.md「平台入口规范文件」节）；**非主导平台各生成一行薄入口文件引用本正文**。模板正文中所有 `<入口规范文件>` 占位一律替换为映射定名后的实际文件名。
> 用法：第二部分逐节给出「写什么 / 格式 / 示例片段」；agents 按问询答案逐节替换为项目实际情况，示例残留内容要清干净。

> ## ⭐ v11.4 设计原则（本模板的最大变更，务必先读）
>
> **入口规范文件 = 常驻区**（平台每次会话自动注入 → 每一轮都在上下文里，成本按会话数累加）。因此它**只放两样东西**：
> 1. **无论做什么都必须遵守的**（硬门禁、纪律红线、指令优先级）
> 2. **无论做什么都必须知道去哪找的**（**规范索引**＝路由表 + **动作 → 必须更新**表）
>
> **其余一切按需加载**：细则、表格、清单、模板——外移到独立文件，入口只留**一行引用 + 什么时候必须去读**。
>
> **为什么这样切**（两条依据）：
> - **供给侧**：一个规则族拥有自己的 owner / 变更节奏 / 入站链接 / 验证方式时，才配独立小文件；强耦合的不拆。
> - **需求侧**：**每个事实只有一个家**——入口文件是「常驻命令」（每条 1–3 行 + 链接它的家），**不属于**它的：故事、范例、情境化流程、以及从已链接的家里复述的任何内容。
>
> ⚠️ **按需加载成立的前提**：**路由表必须完整**。AI 不会去读它不知道存在的文件——所以「规范索引」必须把**每一个**规范文件列全，并说清**什么时候必须读它**。
>
> 📏 **体量门禁（红线⑧）**：生成的入口文件 **≤ 8 KB**（约 2,500 汉字）。依据：各平台自动注入上限里最紧的一档是 Codex 的 32 KiB，Claude Code 40k 字符、DSH 64 KiB；8 KB 为所有平台留足余量，也避免 DSH 的「根文件过大 → 被更具体的子目录文件挤掉」行为。

> **双受众定位**：入口文件给人看 + AI 入场必读（AI 每次入场完整读一遍，token 成本敏感）→ 内容按「三因素」取舍（见产出红线⑤）。
> **产出红线**：
> ① 常用命令必须**实测**（写错构建命令比不写更糟）
> ② 认证/取当前用户约定必须写清
> ③ 敏感信息（内网地址/密码/凭据）不写
> ④ 问询纪律（记忆/会话/工具/写操作确认）落入**正文对应区**——纪律红线进本文件、记忆纪律与签署矩阵进 `<AI协作规范文件>`（模板 32）、低频长流程进附录引用
> ⑤ **三因素取舍（v11.4 强化为「常驻 vs 按需」）**：**常驻**＝无论做什么都要遵守/都要知道（项目事实速查 + 两张表 + 纪律红线）→ **详细但精炼**（表格化、要点化）；**按需**＝细则、清单、表格、模板 → **只留一行引用 + 触发条件**，详情在对应文件；**低频长流程**同样只留引用（内联会让 AI 每次入场白吃 token）
> ⑥ **on/off 标注**：每节标注适用条件（如「仅适用有 HTTP API 的项目」）；生成时按问询答案决定生不生成
> ⑦ **语言生成规则**：多语言对照内容模板全列，生成时只产本项目主语言（+前端语言如有）
> ⑧ **体量门禁**：生成的入口文件 ≤ 8 KB；超了**先外移、再压缩**，不许牺牲硬门禁措辞
> 　 📏 **实测基线（v11.4）**：本模板「示例骨架」块合计 **CJK 1,699 字 + 非 CJK 2,674 字符 ≈ 7.59 KB**（UTF-8；CJK×3 + 其余×1 + 每行 CRLF 2 字节）——**余量仅约 0.4 KB**，因此**再加节/加表前必须同步删减或外移**。复测：抽出本文档 ```` ```markdown ```` 围栏里的内容按上式求和；项目实际产出后再用 `(Get-Item <入口文件>).Length` 复核。

> **技术栈方向**：示例片段分三个方向——**Java/Web**（Spring Boot + Vue，默认示范）、**C++ 后端**（CMake + g++ 服务端）、**嵌入式**（STM32/ESP32 固件）。按 A 组答案取用对应方向；每节「写什么」对所有方向通用。
> **生成时只保留本项目语言**（红线⑦）。

### 1 项目简介【常驻·详细但精炼】
- **写什么**：项目名称、一句话定位、给谁用、当前/演进方向（存量改造时写明「以新需求文档为准，先确认范围」）。不写背景故事。
- **指令优先级声明（必写一行）**：`> 本文档为项目最高指令；与用户当面指示冲突时以用户为准。`——放在文件名下方第一行。
- **必须附带**：文件顶部的「本文件只放常驻内容，其余按需查规范索引」一句（让 AI 与人都不误以为这是全部规范）。
- **开发模式（2 行，合并进本节）**：存量代码怎么维护、新功能怎么走流程。
- **示例片段**：
```markdown
# <项目名>

> 本文档为项目最高指令；与用户当面指示冲突时以用户为准。
> 本文件只放「无论做什么都要遵守 / 都要知道去哪找」的内容；其余规范见文末「规范索引」，按需读取。

## 项目简介
<一句话描述>：<做什么>、<给谁用>。
> 按最新需求（docs/<需求文档>），项目正从 <旧模型> 演进为 <新模型>。存量代码仍是 <旧角色模型>，改造时以需求文档为准，先与用户确认范围。

**开发模式**：存量代码（backend/、frontend/ 现有模块）直接维护，不套用工作流；**新功能/新模块**走模块工作流（见附录「模块工作流」引用）——Planner→Developer→Reviewer→Tester 闭环 + specs 五件套 + 记忆库。
```

### 4 架构关键约定【常驻·详细但精炼，按语言栈生成】
- **写什么**（本项目最重要的约定，缺了后续开发会踩坑）：按主语言生成对应小节——
  - Java/Web：**认证与当前用户**（登录机制 + Controller 取当前用户方式 + 权限模式）+ **统一返回与分页** + **配置红线**
  - C++：接口层→业务层→数据层 + 配置（环境变量/文件）+ 日志分级
  - 嵌入式：应用层→业务层→驱动层 + 中断与任务隔离 + 串口日志

- **只写「后续开发必须知道的约定」，不写框架科普**。
- **示例片段（Java/Web）**：
```markdown
## 架构关键约定
扁平分层：controller → service（接口）+ service/impl（实现）→ mapper → entity/dto/vo。

### 认证与当前用户（关键约定，勿偏离）
- JwtAuthFilter 从 `Authorization: Bearer <token>` 解析 JWT，校验签名 + Redis 中 auth:token:{userId} 一致性。
- **Controller 取当前用户用 `request.getAttribute("userId")` / `getAttribute("role")`**，不是 @AuthenticationPrincipal。
- 权限为服务层按角色过滤数据：Service 方法接收 userId + 各主体 id，按角色缩小查询范围。

### 统一返回与分页
- Result<T> = { code, message, data }；code=200 成功，401 未认证/过期。
- 列表统一返回 Result<PageResult<T>>；分页依赖 MyBatis-Plus 分页拦截器（单页上限 500）。
```

### ★ 6 动作 → 必须更新【v11.4 新增·常驻·**必须原样生成，不允许省略**】

- **写什么**：**触发侧门禁**——以「事件」为键，回答「我做了 X 之后，必须更新什么」。
- **为什么必须有**：产出物清单是以**名词**为键的（「CLAUDE.md 要有什么」），而现实中的遗忘发生在**动作**上（「我加了个脚本」之后没人去想「tools/README 要更新」）。**这张表是防遗忘的主防线**，与记忆库「回答末尾自检第③步·动作回看」、模板 24 阶段 6「文档影响清点」三处联动。
- **示例片段（基本原样保留，可按项目增删行，但不得删表）**：
```markdown
## 动作 → 必须更新（做了 X 就必须更新 Y）

> 本职：**事情做了、文档忘了**是这类项目最高发的失误。下表逐条对照；**任一动作发生后没更新对应文档，不许结束本次回答**。

| 一旦发生了这个动作 | 必须同时更新 | 唯一出处 |
|---|---|---|
| 新增 / 删除 **可执行工具、脚本、命令** | `tools/README.md`（用途 / 参数 / 示例 / 删除演练影响） | tools/README |
| 新增外部依赖 / 改环境要求 | 部署文档；踩过的坑进 `docs/已知坑/` | 各自文件 |
| 新增 / 改 **构建·测试·运行命令** | 本文件「常用命令（实测）」（**必须实测过**才写） | 本文件 |
| 新增 / 改 **接口、路由、权限点** | 功能说明 + 接口清单 + 权限矩阵（**权限类改动三处对齐**） | 各自文件 |
| 新增 / 改 **数据库表、字段** | 数据库设计 + 迁移说明 | 各自文件 |
| 新增目录 / 移动·改名文件 | `memory/file-index.md` | file-index |
| **踩到新坑并解决** | `docs/已知坑/`：新建 `NNNN-*.md` **＋同时**补 README 的规则速查表与坑索引表 | docs/已知坑/README.md |
| 引入新的第三方约定 / 规范 | 对应规范文件 + 变更记录行 | 各自文件 |
```

### ★ 7 规范索引（路由表）【v11.4 新增·常驻·**必须完整，不允许省略行**】

- **写什么**：**每一份项目规范文件一行**，格式固定为「**什么时候必须读** → **哪个文件** → **为什么**」。
- **硬规则（必须随表写上）**：表中「什么时候」成立时，**先读对应文件全文再动手**——**按需加载 ≠ 可以跳过**。
- **生成时**：按问询答案裁剪（没产出的规范不列行）；**至少包含**下表骨架里的常驻行；新增任何规范文件时必须同时在本表加一行（否则 AI 不知道它存在＝按需加载失效）。
- **示例片段**：
```markdown
## 规范索引（什么时候必须读什么）

> **规则**：下表「什么时候」成立时，**先读对应文件全文再动手**。本文件只放常驻内容，细则全在这些文件里——**按需加载 ≠ 可以跳过**。
> 新增任何规范文件时，**必须同时在本表加一行**（否则 AI 不知道它存在）。

| 什么时候必须读 | 文件 | 为什么 |
|---|---|---|
| 写模块 plan / acceptance 之前 | `specs/_样板/`、`docs/AI协作规范.md` | 五件套颗粒度、签署责任与记忆纪律 |
| 改代码之前 | `docs/编码规范.md` | 本项目主语言硬约束（命名/分层/异常/日志…） |
| **遇到报错 / 环境问题 / 工具异常** | **`docs/已知坑/README.md`（先读索引，再按需展开单篇）** | 先查是否已有固定解法，避免重复排查 |

| 找任何文档 / 看全部索引 | `docs/DOCUMENT-INDEX.md` | 导航总索引（人+AI 共享） |
| 开新会话 / 跨阶段交接 | `memory/handoff/`、`memory/project/module-lifecycle-checklist.md` | 上下文交接与阶段 gate |
| 文档排版有疑问 | `docs/中文排版规范.md` | 全角标点 / 中英空格 / 术语对照 |
```

### 8 纪律红线【常驻·每条一句话】
- **写什么**：人定的规矩（人要看到自己定了什么）+ AI 必须遵守。3-4 条，一条一句不展开。
- **示例片段**：
```markdown
## 纪律红线
- **数据库写操作**（DDL/迁移/数据修改）先展示 SQL 获用户确认再执行；只读 SELECT 可直接跑。
- **工具依赖方向**：项目代码禁止引用 tools/；工具被删除后项目必须照常编译（删除演练）。
- **commit/push** 需用户明确允许，不主动执行。
- **动作后必更新文档**：见「动作 → 必须更新」表；没更新不许结束本次回答。
```

### 9 信息闭环图【常驻·v11.4 精简为 3 条主闭环】
- **写什么**：项目内**多边维护信息**的 唯一出处 → 引用方 → 同步方向。目的：**人打开入口文件就能找到任何信息的权威位置**。
- **v11.4 精简**：只画 **3 条主闭环**（模块状态 / 角色行为纪律 / 文档纪律）；**其余闭环（含按问询生成的可选文档节点）移入 `docs/DOCUMENT-INDEX.md` 维护**，本节只留一行指向——避免入口文件被长图撑爆。
- **示例片段**：
```markdown
## 信息闭环图（多处维护信息的唯一出处）

> 规则：改信息时**只改唯一出处**，改完检查引用方无漂移。**完整闭环（含可选文档节点）见 `docs/DOCUMENT-INDEX.md`。**

### 闭环 1：模块状态（进度/验收）
- 唯一出处：任务清单 checkbox（`docs/<演进任务清单>.md`）
- 引用方：`docs/DOCUMENT-INDEX.md` §模块状态 → `memory/project-context.md` → `memory/file-index.md` 模块汇总
- 同步：模块完成后按「收尾四查·进度清单同步」逐项更新引用方；只改一处 = 漂移

### 闭环 2：角色行为纪律（签署矩阵 + 动作标签）
- 唯一出处：`docs/AI协作规范.md`（模板 32 产出；并入时为本文件「AI 协作规范」节）
- 引用方：`memory/project/module-lifecycle-checklist.md` → `agents/*.md` → `memory/logs/`、`memory/agent-activity-log.md`（只用标签不复制表）
- 同步：改矩阵/标签只改唯一出处，引用方一律引用

### 闭环 3：文档纪律（变更记录三要素 + 收尾四查）
- 三要素唯一出处：`docs/AI协作规范.md`；引用方：docs/、specs/ 各文档头部维护声明
- 收尾四查唯一出处：`memory/project/module-lifecycle-checklist.md` 阶段 5；引用方：本文件「动作 → 必须更新」与各模块 plan
```
