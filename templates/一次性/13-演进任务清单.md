# docs/演进任务清单.md 章节模板（模板 13）
> 🗂️ **产出模式**：一次性文档（skill 特化即正式文件，后续修改=更新式：改内容+变更记录+署名）；模板目录：templates/一次性/（v10.0 目录规整）
> 📍 **变更记录方向**：新行追加底部（有人看；见 SKILL.md 文档维护规则第 9 条）

> ⚠️ **维护声明**：本文档修改后必须在末尾「变更记录」表追加一行——`YYYY-MM-DD HH:mm | 变更内容 | 署名`（署名按四段式 实体人-平台-角色@分支（无 git 省略 @分支，如 warmflame-Reasonix-Developer@feat/xxx）；无法确认身份先问用户）。
> **持续维护文档**（E1 选「演进任务清单」时产出；后续每个模块完成/规划都要回来更新）。示例写在开头，agents 按问询答案追加填写，**后续开发持续追加新行/新层**。
> 🔀 **导航互链**：文档导航见 `docs/DOCUMENT-INDEX.md`（模板 26）；各模块当前状态/待办见 `memory/project-context.md` §6/§7（模板 02）；五件套位置见 `memory/file-index.md`（模板 03）——本清单是「未来做什么」的规划，状态与文件位置去那两个看。
> 🌿 **多工作线**：主线一套清单（`docs/演进任务清单.md`）；专项（如权限改造）**单独一套清单**（如 `docs/<专项>任务清单.md`），仿名易混 → **工作线归属以 specs 目录为准**（`specs/`=主线，`<专项>-specs/`=专项），各清单互不含对方条目，同步时按工作线定位（见模板 24 阶段 4「进度清单文档同步」）。

## 第一部分：章节结构一览

```
docs/演进任务清单.md
├── # <项目名> 整体任务清单
├── ## 状态图例           ← ✅ 已完成 / ▶ 进行中 / 📋 待开发 / 🚫 阻塞
├── ## 执行策略总览（从易到难）  ← 分层原则说明
├── ## 第 0 层：地基       ← 账号/权限/审核等基础模块（逐条 checkbox）
├── ## 第 1 层：业务闭环   ← 核心业务模块
├── ## 第 2 层：报表/大屏/预警  ← 数据类（如有，U 组/需求）
├── ## 第 3 层：算法       ← 独立算法服务（如有）
├── ## 第 4 层：外部对接   ← 第三方/可插拔（如有）
├── ## 技术债务（另立模块） ← 债务登记表（M16/U6）
└── ## 变更记录           ← 版本/日期/变更/变更人
```

## 第二部分：详细规格 + 示例

- **状态图例**：统一符号（✅ ▶ 📋 🚫），避免各写各的。
- **分层原则**：地基先行（账号/权限/审核）→ 业务闭环 → 增强（报表/算法/对接），标注「从易到难」理由。
- **每层**：模块条目 + 状态 + 一句话内容 + 关联文档；已完成标注验收结果。
- **技术债务**：`编号 | 描述 | 影响 | 建议`（如「vue-tsc 环境性失败」），债务独立成模块排队。
- **变更记录**：每次任务清单变动记一行（新增模块/完成/重新排期）。
- **编号对齐**：任务清单模块编号与 specs 流程模块编号对齐规则（U9），避免两套编号错位。
