# 中文排版规范 章节模板（模板 27）
> 🗂️ **产出模式**：一次性文档；模板目录：templates/一次性/（v11.0 新增，源自 ISSUE-010）
> 📍 **变更记录方向**：新行追加底部（有人看；见 SKILL.md 文档维护规则第 9 条）
> 🧩 **装配方式**：可选规范模块（见 SKILL.md「规范装配问询」）——问询时问用户「要不要这套中文排版规范」；「要 + 内容多」→ 产出本完整版（如 `docs/中文排版规范.md`），「要 + 内容少」→ 并入 `<入口规范文件>` 编码规范节精要。「不要」→ 不生成。
> 📎 **参考来源**：本模板是对 superpowers-zh `chinese-documentation` 的中文精简提炼，解决「读起来别扭/机翻味/中英挤一起」。

> ⚠️ **维护声明**：本文档修改后必须在末尾「变更记录」表追加一行——`YYYY-MM-DD HH:mm | 变更内容 | 署名`（署名按四段式 实体人-平台-角色@分支（无 git 省略 @分支，如 warmflame-Reasonix-Developer@feat/xxx）；无法确认身份先问用户）。

## 第一部分：章节结构一览

```
中文排版规范
├── 空格规则（中英文/中数/数单位 + 例外）
├── 标点规则（中文用全角 / 英文数字用半角 / 括号与引号）
├── 数字规则
├── 术语处理（保留英文 / 首次中英对照 / 避免过度翻译）
├── 代码与引用格式
└── 写作检查清单（排版/术语/内容/格式）
```

## 第二部分：详细规格（写什么 / 格式 / 示例）

**目标**：让文档专业、好读、不出戏；核心原则——**排版服务阅读、规范服务一致、内容服务读者**。

### 1. 空格规则
- **中英文之间加空格**：好 `使用 Git 进行版本管理`；坏 `使用Git进行版本管理`。
- **中文与数字之间加空格**：好 `本次更新包含 3 个新功能`；坏 `包含3个新功能`。
- **数字与单位之间加空格**：好 `不超过 5 MB`、`200 ms`。
- **例外（不加空格）**：度数、百分比等——`32°C`、`95%`（不写 `32 °C`、`95 %`）。
- **链接前后加空格**：好 `请参考 [官方文档](https://example.com) 获取信息`。

### 2. 标点规则
- **中文语境用全角标点**：好 `注意：该接口需要鉴权，请先获取 Token。`（全角冒号/逗号/句号）；坏 `注意:该接口需要鉴权,请先获取 Token.`。
- **全角标点与英文/数字之间不加空格**：好 `项目使用 MIT 协议`；坏 `MIT 协议 ，`。
- **括号**：中文语境用全角 `（详见下方）`；括号内有英文或数字用半角 `Spring Boot (v3.2.0)`；纯英文用半角 `See (README.md)`。
- **引号**：中文推荐直角引号 `「确定」按钮`，嵌套用 `『』`；或团队统一用弯引号，前后一致即可。
- **英文/代码内容用半角标点**：`Run npm install, then npm test.`（不写中文标点）。

### 3. 数字规则
- 技术参数用半角阿拉伯数字：`支持最多 100 个并发连接`、`v2.1.0`、`8080`、`200`。
- 不要用中文数字写技术参数（`一百个` ❌）。
- 金额/计数务必标注单位避免歧义：`total_amount: 9900（单位：分，即 99.00 元）`。

### 4. 术语处理
- **保留英文**：专有名词（React/Kubernetes/MySQL）、行业缩写（API/SDK/CLI/ORM/CI/CD）、命令与代码（`npm install`）、协议标准（HTTP/TCP/IP/JSON）、无公认翻译的术语（debounce/middleware）。
- **首次出现标注中英对照**：好 `本系统采用消息队列（Message Queue）实现异步通信`；后续出现直接用。
- **避免过度翻译**：好 `在 Controller 层做参数校验，Service 层处理业务逻辑`；坏 `在控制器层做参数校验，服务层处理业务逻辑`。
- **避免机翻味 / 欧化长句**：`这个函数用于计算折扣，更多信息见文档。`（不是"这个函数被用来…如果你想要…请参考…"）；长句拆短、少被动语态、少冗余代词。

### 5. 代码与引用格式
- 代码块标注语言类型：` ```bash`、` ```typescript`。
- 标题层级不跳级、图片有 alt 文本、链接可访问。

### 6. 写作检查清单（发布文档前逐项自查）
- **排版**：中英/中数有空格；中文全角标点；英文代码半角；无全半角混用。
- **术语**：专有名词保留原文；首次术语有中英对照；未过度翻译；术语前后一致。
- **内容**：句子简短无欧化；少被动语态；用列表/表格结构化；代码示例可直接运行；无机翻味。
- **格式**：标题层级正确；代码块标语言；链接可访问；图片有 alt。
