# memory/project-context.md 章节模板（模板 02）
> 🗂️ **产出模式**：一次性文档（skill 特化即正式文件，后续修改=更新式：改内容+变更记录+署名）；模板目录：templates/一次性/（v10.0 目录规整）
> 📍 **变更记录方向**：新行插顶部（纯 AI 看；见 SKILL.md 文档维护规则第 9 条）

> **一次性创建 + 持续维护**（各阶段退出前必须更新——记忆库三件套是阶段交接硬性校验）。示例=结构示范，agents 按问询答案填充；「更新日志」每次维护追加一行。
> 定位：**共享上下文唯一入口**——新 agent 入场第一份必读文件，项目状态、模块清单、决策、教训都在这里。

## 第一部分：章节结构一览

```
memory/project-context.md
├── # 项目上下文记忆库
├── > 🔒 记忆库纪律声明   ← 触发条件/末尾自检/入场核对（可选，参照 CLAUDE.md C 区「记忆库纪律」节）
├── ## 1. 项目概述        ← 名称/简介/创建时间/最后更新/版本
├── ## 2. 技术栈          ← 表：类别/选型/备注
├── ## 3. 团队成员        ← Agent 角色 + 协作/通讯规则
├── ## 4. 已完成模块清单  ← 表：模块/名称/版本/状态/验收结果/完成日期
├── ## 5. ADR 索引        ← 架构决策记录索引
├── ## 6. 当前迭代状态    ← 状态符号表(📋🔧👀🧪✅) + 正在开发 + 下一模块 + 阻塞项 + 流程图
├── ## 7. 待办事项        ← checkbox 清单（短期/长期）
├── ## 8. 关键技术决策记录 ← 问询备注/开发中决策都记这里
├── ## 9. 历史教训        ← 踩过的坑 + 避免方法
└── ## 更新日志           ← 日期/更新人/内容（每次维护追加）
```

## 第二部分：详细规格

### 1. 项目概述
- 表格：`名称 / 简介 / 创建时间 / 最后更新（更新人）/ 当前版本`；最后更新每次改完记得刷新——**与末尾「更新日志」表第一行（最新一行）同步**（v10.3，防头部/末尾日期不一致）。

### 2. 技术栈
- 表：`类别 | 选型 | 备注`（后端/前端/数据库/缓存/ORM/API 文档/部署），与 **CLAUDE.md A3 技术栈**一致（此前的「tech-stack.md」引用不存在，已修正——死引用示例）。

### 3. 团队成员
- 角色表（Planner/Developer/Reviewer/Tester）+ 协作规则（谁产出什么、交接方式）+ 通讯规则。

### 4. 已完成模块清单
- 表：`模块编号 | 模块名称 | 版本号 | 状态 | 验收结果 | Tester | 完成日期`。
- **验收通过才放入已完成清单**；未验收的留在待办/迭代状态。

### 6. 当前迭代状态
- **模块状态符号表（与模板 24 RECOVERY R1 对齐，恢复/入场一眼定位）**：
  - 📋 待开发 / 🔧 开发中 / 👀 待审查 / 🧪 待测试 / ✅ 已完成
- 正在开发的模块（含状态符号 + 最新进展一句话）、下一个待开发模块、阻塞项表（`阻塞项/原因/影响/报告人/时间`）、工作流程图。
- 示例：`正在开发：🔧 module-002（T2 编码中，879 绿）`

### 7. 待办事项
- `- [ ] 内容` 清单，按短期/长期分组；完成改 `[x]` 并注明日期结果。

### 8. 关键技术决策记录
- 编号列表：`决策标题：内容 + 原因 + 日期`。**问询轮「本组备注」有实质内容的都记这里**（C 组、U3 业务规则 vs DB 冲突等）。

### 9. 历史教训
- 踩过的坑一句话 + 避免方法（如「Excel 数值型截断学号 → 模板文本格式+字符串解析」）。

### 更新日志
- 表：`日期 | 更新人 | 内容`（每次更新追加，不覆盖历史）。

