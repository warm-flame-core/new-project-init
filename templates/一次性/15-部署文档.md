## 第二部分：详细规格 + 示例

### 构建产物
- 部署前在开发机生成：后端 jar 路径、前端 dist 路径；**写明打包命令与已知坑**（如「勿用 npm run build：vue-tsc 环境性失败，用 vite build」）。
### 后端部署
- JDK 版本、启动命令（java -jar）、必要环境变量（数据库地址/密钥）、端口。
### 嵌入式项目适配（按 A 组选栈取用）
- 构建产物：固件 `.elf/.hex/.bin`（交叉编译链 arm-none-eabi-gcc / PlatformIO）。
- 烧录：`platformio run -t upload` / OpenOCD（J-Link/ST-Link）/ 串口 ISP。
- 串口日志：`platformio device monitor` / minicom / 串口助手（波特率与日志分级约定）。
- 部署 = 烧录 + 上电自检（替代服务器部署）；已知坑：交叉编译链版本 / 驱动 / USB 枚举。
### 前端部署
- nginx 配置要点（静态目录、/api 代理到后端、端口）。
### 数据库与依赖
- MySQL 迁移脚本按顺序执行清单；Redis 要求；MinIO 等外部服务（如有）。
### 配置密钥
- 密钥从哪里来（环境变量/application.example.yml 模板，E7）；**严禁在文档写真实密码/内网地址**。
### CI/CD（可选，U13=要时生成；U13=暂不/已有则整节跳过——修复 U13 问询→模板断链）
- **流水线文件位置**：如 `.github/workflows/*.yml` / `.cnb.yml` / Gitee Go / Coding CI / 极狐 CI（按实际平台）。
- 触发条件（push 到哪分支）、构建命令（与「构建产物」一致）、测试命令（`mvn test` 全量）、部署步骤（产物 → 服务器/镜像）、**CI 环境变量**（从 secrets 注入，不写明文）。
- 注意：CI 中的构建/测试命令必须与本地实测一致（写错构建命令比不写更糟）。
### 已知坑 / 排查
- 工具链版本坑（U6）、常见启动失败排查（端口占用/连不上库/Redis 未启动）。
- **每条已知坑按「现象 / 根因 / 固定解法」三要素写**（U15/T6 方法类产物落点），如：现象=控制台中文乱码；根因=代码页非 UTF-8；解法=先执行 `chcp 65001`。跨项目通用的记入全局记忆。

### 示例（结构示范）
```markdown
# PTB 部署文档

## 构建产物（部署前在开发机生成）
- 后端 jar → backend/target/app.jar
- 前端 dist → frontend/dist/
- ⚠️ 勿用 `npm run build`：vue-tsc 环境性失败（技术债务），用 `vite build`

## 后端部署（JDK 17）
```bash
java -jar app.jar --spring.profiles.active=prod
```
- 环境变量：MYSQL_HOST / REDIS_HOST / JWT_SECRET

## 前端部署（nginx）
- 静态目录指向 dist/；`/api` 反向代理到后端 8080

## 数据库与依赖
- 按顺序执行 sql/schema.sql → sql/V2__*.sql …
- Redis 必须启动（登录 token 依赖）

## 启动和测试
1. 启动 Redis → 2. 初始化数据库 → 3. 启动后端 → 4. 启动前端
- 验证：platform_admin 登录成功、首页 4 卡片非空

## 已知坑 / 排查
- 连不上库：确认 MYSQL_HOST 内网可达；端口占用：netstat 检查 8080/3000
```
