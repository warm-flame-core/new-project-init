## 第二部分：详细规格

- **判定标准**：会在 **2 个以上场景复用**的工具 → 固化进 tools/；一次性工具用完即弃，但用法记入 memory/logs（避免重造）。
- **依赖方向硬规则**（v5.2 起强制）：
  - 单向依赖：`工具 → 项目` 允许（可复用项目依赖库/配置/工具类）；**`项目 → 工具` 禁止**——项目代码严禁 import/引用 tools/ 下任何内容。
  - 可删除性：任何工具被 delete 后，项目必须照常编译运行。
  - **落地验证（删除演练）**：固化时删掉该工具 → 跑 `mvn compile`（或前端 `npm run build`）→ 通过才允许；结论记入复用记录。
- **工具列表（每工具一节）**：
```
### <工具名>：<一句话用途>
- 用途：…
- 用法：`…`（命令示例）
- 参数：…
- 输出：…
- 依赖：…
- 用户确认：只读直接跑 / 写操作必须展示 SQL 或清单获用户确认（U12）
- 复用记录：…
```
- **安全说明**：含凭据工具（连接串）→ **本地保留不入库**（.gitignore `tools/`）；写操作工具执行前必须用户确认；凭据权威来源（配置文件）与工具内置一致，改动两处同步。
- **使用注意（固定解法沉淀处，U15 / T6 方法类）**：
  - 反复遇到的问题（如 Windows 中文乱码）按「现象 / 根因 / 固定解法」三要素记在此处或 CLAUDE.md 已知坑；**跨项目通用的记入全局记忆**（下次任何项目初始化直接预置）。
  - 环境编码：Windows 控制台中文乱码先 `chcp 65001`（UTF-8 代码页）再运行工具；Java 工具输出乱码加 `-Dfile.encoding=UTF-8`。
  - 内网依赖：连库工具需在内网才能连共享库（地址不可达时连接超时，非工具故障）。
  - **工具构建语言（T7）**：与项目主语言一致，或先检测本机环境（python/node/go 可用性）后选用；**无论什么语言构建，临时工具都遵守依赖方向硬规则 + 删除演练 + 含凭据本地保留**。
- **复用记录（追加式）**：`日期 | 模块 | 工具 | 场景 | 结果`——每次复用追加一行，证明工具价值、避免重复造。
