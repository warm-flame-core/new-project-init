## 第一部分：简化章节递归（结构一览）

```
specs/module-XXX/review-report.md
├── # 审查报告 — Module-XXX: <名称>
├── ## 第 N 轮审查（<日期>）
├── ## 1. 审查结论        ← 结论先行：✅ PASS / ❌ 不通过（0 阻塞 + N 建议）
├── ## 2. 问题列表
│   ├── ### 2.1 需求偏差问题（实现与意图不符，回用户确认）  ← 标记【需求偏差】
│   ├── ### 2.2 阻塞问题（必须修复才能通过）  ← 每问题：现象/位置/根因/修复示例
│   └── ### 2.3 建议改进（不阻塞但建议修复）
├── ## 3. 验收标准核对    ← 验收项 → 对应代码 → 实测备注（逐条）
├── ## 4. 架构评估        ← 分层/依赖方向/一致性
├── ## 5. 安全评估        ← 注入/越权/密钥/敏感数据
├── ## 6. 架构决策记录（ADR）← 审查发现的架构变更
├── ## 7. 审查检查清单    ← 命名/返回格式/分层/异常/日志/长度/安全
├── ## 8. 实测验证记录    ← 真实跑过的命令与结果
└── ## 9. 结论
```

> ✅ **产出后核对（v10.1）**：对照上方结构一览——①每轮审查独立小节（第 N 轮，追加不覆盖）②问题分级（需求偏差/阻塞/建议）③验收标准逐条核对非抽样 ④每问题含位置/根因/修复示例。

## 第二部分：详细规格

### 第 N 轮审查
- 首轮写 `## 第 1 轮审查（<日期>）`；修复复审时在文件**末尾追加**第 2 轮小节（保留历史，不覆盖）。
- 标题下注明审查人/日期/被审查提交（如 commit `aab740b`）；审查人按三元组 `<人>-<Reviewer>-<实例>`。

### 1. 审查结论（结论先行）
- 一句话：`✅ PASS（0 阻塞 + 0 需求偏差 + N 建议）` 或 `❌ 不通过（N 阻塞 + N 需求偏差 + N 建议）`。
- 问题分三级：**需求偏差**（实现与用户真实意图不符，标记 `【需求偏差】`，需回用户确认后再修——流程见模板 24 阶段 3）/ **阻塞**（必须修复才能进入测试）/ **建议**（不阻塞但值得修）。

### 2. 问题列表
- 每个问题必须含：**现象 + 代码位置（行号）+ 根因 + 修复示例（代码片段）**，禁止只写「XX 有问题」。
```
### 2.1 需求偏差问题（实现与用户真实意图不符，需回用户确认）
#### 需求偏差 1: <一句话问题> 【需求偏差】
- 位置：`File.java` L120-135
- 实现按：…（当前实现）
- 需求表述：…（plan/需求文档原文）
- 差异点：…（请用户确认以哪个为准，未确认前不修复）

### 2.2 阻塞问题（必须修复才能通过）
#### 阻塞 1: <一句话问题>
- 位置：`File.java` L120-135
- 现象：…
- 根因：…
- 修复示例：
  ```java
  // 修复后写法
  ```
```

### 3. 验收标准核对（核心差异点）
- 把 acceptance-criteria.md 的验收项**逐条**列成表，标出对应代码位置与实测结果：
```
| 验收项 | 对应代码 | 实测备注 |
|--------|----------|----------|
| 匿名 401 | SecurityConfig + RestAuthenticationEntryPoint | 实测 curl 返回 401 JSON ✅ |
```
- **验收标准 = 最终实现（v10.12，ISSUE-004）**：若审查发现问题并**修了代码**，必须**同步核对 acceptance-criteria.md 的对应验收项描述**——先更新 acceptance 到与最终实现一致的表述（如权限点、返回语义），再签 PASS；**Reviewer 签字代表「验收标准已与最终实现逐条一致」**，不能出现「acceptance 还是旧描述、代码已改」的脱节。

### 4. 架构评估 / 5. 安全评估
- 架构：分层隔离、依赖方向（Controller→Service→Mapper）、与既有模式一致。
- 安全：SQL 注入（参数化）、越权（按实体 ID 校验）、密钥硬编码、敏感数据日志。

### 6. 架构决策记录（ADR）
- 审查中发现架构变更 → 按 ADR 责任规则（发现者撰写、Planner 审批）记录；无则写「无」。

### 7. 审查检查清单
- 命名 / 统一返回格式 / 分层 / 依赖方向 / 异常处理（无空 catch）/ 日志 / 代码长度（≤200）/ 安全逐项打勾。

### 8. 实测验证记录
- 真实跑过的验证（非纸面）：命令 + 结果，如 `mvn test` 82/82、bcrypt 种子 hash 交叉实测、curl 全链路。
