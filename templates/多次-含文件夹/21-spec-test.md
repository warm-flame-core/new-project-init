## 第二部分：详细规格

### 1. 测试概览
- 表：测试类型（单元/集成/回归）、用例数、执行时间、执行人。
- 回归测试**必须全量跑**（`mvn test` 全量，不是只跑新增）。

### 2. 覆盖率报告
- 按模块/类给出用例数与覆盖率；核心业务逻辑 ≥80%（可按 plan 调整并说明）。
- 给出数字证据：如「全量 100/100 BUILD SUCCESS（既有 82 回归 + 新增 18）」。

### 3. 验收标准核对
- 对照 acceptance-criteria.md **逐条**核对：`- [x] <验收项>（结果）`。
- 分节：3.1 功能验收（对应 acceptance §1）、3.2 非功能验收（对应 §2）。

### 4. 失败详情（含环境性失败归因——核心差异点）
- 每个失败：现象 + 根因 + **归因分类**：
  - **环境问题导致的失败/跳过**（依赖缺失、未 mock、工具链不兼容、collection 失败）→ 修环境或修测试，**不算真实回归**
  - **真实回归** → 才通知 Developer 修复
- 禁止把环境性失败写成真实回归（本项目 vue-tsc 环境性失败即属此类）。
```
### 失败 #1
- 现象：npm run build 的 vue-tsc 报类型错误
- 根因：vue-tsc 1.8.27 ↔ TS 5.9.3 不兼容（工具链问题）
- 归因：🔧 环境性失败（非本模块回归）；用 vite build 验证前端构建 ✅
```

### 5. 真实环境冒烟（强制前置）
- 对含 DB/外部依赖交互的模块，**测试通过前必须用真实 DB（或真实依赖）跑一次冒烟**，至少覆盖验收标准核心路径。
- 记录：连接的真实环境（共享库地址/本地库）、覆盖路径、结果。
- **数据清理记录**：冒烟临时数据清理情况（如「已恢复基线，user 52 / student 17」）。

### 5.5 测试发现备注（超验收范围的行为/发现）
- 测试中发现的**不在 acceptance 范围内**的行为/发现（如批量操作缺少某枚举、接口返回语义与预期有出入但无副作用），**记录不隐藏**：
  - 现象 + 是否影响验收 + 建议（修复/记录为已知备注/留后续模块）
  - 示例：「批量未知操作类型返回 200+逐条失败明细而非整批 400——fail-closed 无副作用，建议循环前校验，非本模块验收范围」
- 原则：超范围 ≠ 回归；记录清楚即可，不阻塞验收（除非影响核心路径）。

### 6. 测试结论
- 结论（✅ 通过 / ❌ 不通过）+ 测试人 + 日期 + 遗留项；测试人按三元组 `<人>-<Tester>-<实例>`。
- 不通过时输出失败详情，通知 Developer 修复，修复后重测（追加轮次）。
