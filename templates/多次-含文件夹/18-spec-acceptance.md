## 第二部分：详细规格

### §0 验收环境前置（必填）
- **SQL 执行顺序**：本轮依赖哪些迁移脚本，按顺序执行（如 `sql/schema.sql` → `sql/V2__*.sql` … `sql/V15__*.sql`）。
- **种子账号清单**：验证用账号 + 密码规则 + 角色（只写账号名与角色，密码只写规则不写明文）。
- **返回信封**：统一返回结构说明（如 `{code, message, data}`，code=200 成功、401 未认证/过期）。
- **关键语义约束**：本次验收必须遵守的语义（如「登录失败 400 非 401」「匿名访问受保护端点 401」）。

> 🎯 **lead 风格示例（脱敏自 module-004 §0，对齐颗粒度基准）**——环境前置要写到「Tester 不用猜」：
> ```
> ## 0. 验收环境前置
> - 后端已启动（含 MySQL/Redis，共享库或本地重建同 schema + test-data）；前端可启动。
> - 数据库脚本执行顺序：`sql/schema.sql` → `sql/test-data.sql`（TD-4 修改后，二者种子 hash 均为实测值 `<hash>`）。
> - 统一返回信封：`{"code":200, "message":"...", "data":{...}}`（`Result` 实体，字段为 `message`）。
> - **前端 401 语义约束**：`frontend/src/api/request.ts` 将 HTTP 401 与业务码 401 均视为「会话过期」→ 清 token 跳登录页。因此**登录失败（密码错误）必须返回业务码 400（HTTP 200 + body code 400）**，绝不返回 401。
> - 种子账号（全部密码 <密码规则>）：`<账号1>`(<角色>)、`<账号2>`(<角色>)…
> ```
> **自检**：Tester 拿到 acceptance 能否不追问就开测？①脚本/数据/环境是否写全 ②关键语义约束是否显式标注（尤其影响前端行为的）③账号清单是否含回归覆盖的所有角色。

### §1 功能验收（按需求分节 checkbox 清单）
- 按需求条目分节（`### 1.1 <需求标题>`），每条下用 checkbox 列验收项：
  - 核心功能（主流程必须通过）
  - 边界条件（空值/超限/重复/跨校冲突）
  - 异常场景（失败/回滚/权限不足/越权）
- 格式：
```
### 1.1 <需求标题>
- [ ] 场景 1：Given… When… Then…（预期结果）
- [ ] 场景 2：…
```
- 每条验收项要**可执行**——Tester 能照此操作并判断过/不过，禁止模糊表述。
- **单测清单预列（v10.12，ISSUE-007）**：§1 每节可选加一行「**对应单测用例**」（用例名 + 断言），或标题下明确写「**单测 = 本 acceptance 各节转测试用例**」——让 Tester 的单测覆盖**来源明确、预先列出**，避免边写边补导致覆盖不完整（perm-007 教训：acceptance 无单测清单，Tester 边写边补 10 用例）。

### §2 非功能验收
- **2.1 安全验收**：认证/权限/越权/敏感数据（按 F2/F3 问询答案特化）。
- **2.2 代码质量验收**：注释覆盖率 / 命名规范 / 分层架构 / 代码长度（≤200 行/模块）/ 编译检查（mvn compile / npm run build）。

### §3 可运行验证命令
- 表格列出：命令 + 预期输出（curl 示例、浏览器步骤、构建命令）。
- **字段名/计数实测（v10.2）**：验证命令的字段名与预期计数，必须对照实际数据模型（建表脚本/迁移/实体定义）实测确认，不凭文档或记忆推断——防验收时才发现字段名错或计数错（脱敏实例：查询字段实为 `code` 非文档所写 `permission_code`；模块码实际 10 个非预期 9 个）。
```
| # | 验证项 | 命令/操作 | 预期输出 |
| 1 | 登录 | curl -X POST ... | HTTP 200 + code=200 |
| 2 | 构建 | cd backend && mvn test | BUILD SUCCESS + N/N |
```

### §4 验收结论（Tester 签署）
- 签署人/日期/结论（通过 / 不通过 / 有条件通过）。
- **署名按四段式**：`<实体人>-<平台>-<Tester>@<分支>`（无 git 省略 `@分支`），如 warm-flame-core-Reasonix-Tester@feat/xxx；无法确认身份先问用户。
- **实测记录**：测试数字（如「后端 100/100 + 真实冒烟全矩阵 + 浏览器端到端」）、冒烟矩阵覆盖、**数据清理记录**（冒烟临时数据已恢复基线，账号数）、遗留项标注。
- 每轮测试失败 → 输出失败详情 → Developer 修复 → 复审后重新执行，结论与轮次对应。
