# 验证走查：全新项目场景（testing/）

> 用途：**skill 迭代验证**（主文件「skill 迭代大前提」第 4 条落地）。每次改动问询/流程后，按受影响场景跑一遍走查，确认流程通顺、无遗漏。
> 走查方式：模拟一次真实调用（可以带用户真实回答走查，也可用预设答案演练），逐项核对，结果记入本文件末尾「走查记录」。

## 前置

- [ ] 读取 `SKILL.md` 全文（含本次迭代的改动点）
- [ ] 确认改动点在本场景的落点：问询分级（🔴/🟡）、第 0 轮、全新问询 11 轮

## 走查步骤

1. **第 0 轮能力摸底**
   - [ ] Q0-1 熟悉程度：🔴 一次一个，答案影响后续措辞
   - [ ] Q0-2 概念铺垫：新手/② 必答，熟手可跳过
   - [ ] 措辞切换正确（新手先解释概念再问 / 熟手直接术语）

2. **A 组（第 1 轮）问询分级验证**
   - [ ] 🔴 A0 产品形态：一次一个，未与其他题混问
   - [ ] 🔴 A2 技术栈主选：一次一个，附「推荐 + 权衡」
   - [ ] A2-2~A2-5 跟随批量（带推荐默认）
   - [ ] 整轮提供「以上都用默认」快进入口

3. **B/C 组关键决策验证**
   - [ ] 🔴 B1/B2：一次一个，解释「精简 vs 完整」差异
   - [ ] 🔴 C1 memory/ 入库：一次一个，讲清利弊
   - [ ] 其余 B/C 题批量带默认

4. **问询纪律验证**
   - [ ] 每轮末尾「本组备注（填空）」存在
   - [ ] 答不上来的题目给推荐默认并标注「可改」

5. **产出与确认**
   - [ ] 每份文件产出后先给用户确认再做下一份
   - [ ] 收尾四段式（总结/怎么开始用/日常协作提醒/求助路径）
