# 验证走查：中途加入场景（testing/）

> 用途：**skill 迭代验证**（主文件「skill 迭代大前提」第 4 条落地）。每次改动中途流程/探索规则后跑一遍。
> 走查方式：模拟一次「已有代码、无规范体系」的中途加入调用，逐项核对。

## 前置

- [ ] 读取 `SKILL.md` 全文（含本次迭代改动点）
- [ ] 确认改动点在本场景的落点：信息分层原则、中途 M 组问询（7 轮）、🔴/🟡 分级

## 走查步骤

1. **探索先行（动口前先动手）**
   - [ ] 先跑 `git status` + `git log` + 目录 + 已有规范文件盘点
   - [ ] 实测构建/测试/运行命令（真实跑，不猜）
   - [ ] 已有规范文件判断：有 CLAUDE.md/AGENTS.md → 改进不新建

2. **信息分层原则验证**
   - [ ] 进度状态类 → 用户口述为准（不自己推断）
   - [ ] 技术事实类 → 代码实测为准（文档过时以代码为准）
   - [ ] 两类权威来源不混用

3. **M 组问询分级验证**
   - [ ] 🔴 M2 已有规范文件：一次一个
   - [ ] 🔴 M5a 存量改造定位：一次一个（渐进 vs 重写 vs 混合）
   - [ ] M7 密钥在仓库：单独确认（安全）
   - [ ] 其余 M 组批量带默认
   - [ ] M16b/M16c：按答案决定补问或跳过

4. **生成期异常处理验证**
   - [ ] 生成文档时发现与代码实测不符 → 停下报告，不硬套模板
   - [ ] 用户裁决后才继续

5. **记忆库建立验证**
   - [ ] M9 已完成模块补记（git log 复盘）或从今起记
   - [ ] 入场核对流程写入产出文档

6. **跨平台强门禁（v11.0）**
   - [ ] 场景确定为「中途」后，**先读 `references/场景/中途-问询.md` 全文**再开始问询（未读=违规；借口表见 SKILL.md「跨平台强门禁」节）
   - [ ] 读完后按文件内 M 组题库 + 信息分层原则执行，不凭 SKILL.md 骨架直接问
   - [ ] 平台入口映射与规范装配问询（27-31）随装配组逐项走（见全新走查第 7/8 节，中途场景同样适用）
